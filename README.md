# NetBox OA

面向 **NetBox 4.4.x - 4.6.x**（已验证 4.4.2 及 4.6.2）的轻量工作流插件，Python 包为 `netbox_oa`。
当前兼容范围为 NetBox 4.4.2 至 4.6.x；其他主版本需要单独集成验证。

提供流程定义、草稿申请、顺序审批、拒绝、撤销、审批组校验和 FSM 转换历史。
每个节点由指定 NetBox 用户组中的任意一名有权限的成员处理。
维护工单模块提供按阶段办理、退回补正、转办和加签；通用审批模块仍保留原有顺序审批行为。
维护工单的全部审核和加签节点禁止发起人审批自己的工单或验收单，超级管理员也不例外。该约束覆盖同意、退回、快捷办理及审核签名；转办和加签不能指定发起人为审批人。发起人的草稿、修正、验收申请和上传操作仍可正常办理。
当前不包含条件分支、通知推送、EIP 自动同步或对 NetBox 业务对象的自动写回。

## 外购合同关联工单

同时启用 `netbox_contract` 和 `netbox_oa` 后，外购合同详情通过现有 `right_page` 插槽
注入“服务工单”原生表格，由 OA 脚本定位付款区块并将表格移至其上方，无需修改合同插件。
列表按 `contract_id` 精确关联，包含所有状态的
维护工单，默认按创建时间倒序，每页 25 条；排序和分页使用 `oa_orders-` 前缀，保留合同页其他列表参数。
付款筛选按付款名称包含当前工单编号匹配（忽略大小写），仅显示当前合同下有查看权限的非模板付款。
列表“付款情况”在匹配多笔付款时优先显示问号，悬停提示“存在多笔付款”；单笔付款按状态显示：未纳入付款为空心减号，计划为一个对号，已提交为两个对号，已支付为三个对号；悬停显示文字。状态代码沿用合同插件配置的“计划、已提交、已支付”。无付款查看权限时显示锁形图标。

创建时间显示为 `YYYY-MM-DD`；每行右侧提供描边图标按钮“查看办理流程”和“查看材料”，
保留悬停提示，不显示操作列标题。按钮在当前页的带遮罩弹窗中打开，只读展示现有流程图、办理记录和
材料预览。材料可下载或打印，不提供办理、上传、覆盖、删除或返回审批入口；正常 OA 工作台仍可按权限维护。
流程查看直接复用工作台“审批经过”的共享模板，包括状态图例、完整流程图及“详细办理记录与意见”横向节点，
在弹窗中适当收紧边距和节点间距、缩放流程图，保留详细意见、退回说明及外部单号。
工作台与合同弹窗均按本工单启动时保存的流程快照展示，流程配置调整不替换在途工单环节；页面提示工单完成不代表实际付款或收款。
弹窗支持关闭按钮、Esc 和关闭后焦点返回，加载失败或权限不足时显示提示。

列表沿用 OA 工单查看权限；弹窗还校验合同权限和工单所属合同，任务、记录和材料分别按现有权限过滤。
没有 OA 工单查看权限时不显示此区块。此功能无需数据库迁移；部署后需重启插件服务并收集静态文件。

## 维护服务工单

流程名称为“代维单位维护服务工单流程”，用于流程定义页面、菜单及新发起流程的操作记录。

工作台入口为 `/plugins/oa/maintenance/`，采用列表与详情双栏布局。
界面以 NetBox 4.4.2 为兼容基线，使用原生标准尺寸按钮和 `--tblr-*` 主题变量（保留 `--bs-*` 回退），
查看、资料库、签名、上传、编辑及返回等辅助操作统一使用 NetBox 原生 `btn-ghost-*` 无边框样式，悬停显示语义色背景；
工作台、流程图、材料审阅和上传弹窗支持深色与浅色主题；嵌入页实时跟随父页面主题，独立签名、核验页跟随系统主题。
打印纸张、二维码和签名画布保持白底；部署 UI 更新后需重新收集静态文件并刷新浏览器。
“发起维护服务工单”页复用 NetBox 原生新增对象模板和横向表单字段渲染，提供创建页签、必填及错误提示、
取消、创建和“创建并添加另一个”操作；合同选择仍自动带入服务单位和服务省市。
支持待办工单、待付款工单（本人发起且处于“生成付款”或“付款”环节，这两个环节的本人工单不再显示在待办页）、代办工单、已办工单（含本人发起及本人已完成办理节点的工单，排除草稿和当前待本人处理的工单）、关注工单、全部工单，以及阶段、当前节点、工单号、
服务单位、合同筛选，以及最新发起和等待时间排序。“可代办”工单统一放入代办页，不在待办页显示；待办页保留分配给本人或本人所在组的任务及本人发起的可编辑草稿，管理员和工单负责人也不显示他人草稿。列表卡片展示工单编号、待办状态、发起人 - 发起日期、
当前阶段与节点；管理员代办单独标记为“可代办”。
“服务工单用印”和“验收用印”期间，工单同时显示在发起人的待办中，并计入待办统计；这仅增加用印跟进提醒，实际办理权限仍按当前任务分配控制。
详情中间展示事项说明、材料和当前办理节点，意见与操作按钮直接放在当前节点内。
同意、退回补正、加签和转办成功后显示对应结果，清除筛选及原工单选择，返回待办工单列表。
自动选中列表第一条并回到顶部；无待办时显示空列表。
操作失败保留当前工单、意见及错误提示。此交互更新部署时需收集静态文件并刷新浏览器。
审批经过独立显示在最右侧，展示已有审批环节，保留动作、办理人、时间和两行意见摘要；可用按钮切换紧凑模式，空间不足时自动收为图标栏。
紧凑模式为 50px 单图标栏，节点仅展示 24px 环节单字图标，以颜色和边框区分当前、已完成及退回状态；悬停查看完整信息，点击定位完整审批记录。顶部标准按钮纵向排列，记录区独立滚动；收窄后的空间分配给中间办理区。
切换工单和异步更新时保留手动选择的模式。自动折叠阈值依据工作台实际宽度，兼容 NetBox 侧边导航。
当前所需材料以紧凑文件卡片展示，其余资料统一进入资料库；资料管理侧栏通过标签页切换当前文件、
版本记录与上传修订。完整信息、转办和加签使用独立操作面板，不使用嵌套折叠列表。
审批时点击材料卡片的“审阅”图标，在当前页面侧滑打开审阅面板并选中该材料；左侧索引可切换材料和文件。
材料索引保留逐份列表，材料标题使用主色加粗和分组底色；同类材料仅一份时隐藏份号文字，多份时份号作为二级目录缩进，用印后、审批件、电子版、扫描件及维护图标按实际数量靠右连续排列，当前版本保留选中高亮，份号行不填充。工作台及合同内嵌材料页统一遵循此规则。
材料审阅右侧每次只显示一个文档，通过左侧材料类型、份号或版本图标手动切换，目录同步选中。滚轮、翻页键和空格仅用于当前文档，不自动切换材料。PDF 直接使用浏览器内置阅读器预览原文件，电子表单在独立框架内显示，图片按原比例展示；插件不引入 PDF 渲染库。浏览器提供的搜索、缩放、打印及下载功能按浏览器自身能力呈现；扫描件搜索取决于原文件是否含文字层。切换时按需加载目标文档并释放上一份预览，下载 / 打印入口可查阅原文件。
展示页支持填写表单、PDF 和 PNG/JPEG 扫描件，文件索引与预览均遵循工单和材料查看权限。
可上传节点的材料索引按份提供“⋮”维护菜单，可直接上传覆盖对应材料；覆盖保留份号和历史版本。
具有材料删除权限的当前经办人可删除对应材料；删除保留原文件及审批记录，但不再作为当前提交依据。
用印后上传节点只维护用印件，审批原件保持可查阅。此功能需部署迁移 `0023_document_removed_at` 并更新静态资源。
历史首次展示最近 50 条，支持加载更早记录。
完整审批经过下方的详细办理记录按时间顺序展示为圆点连接的横向时间轴，每次办理记录独立为一个节点，不按阶段分组；办理人、时间、完整意见和外部单号直接显示在各节点下方，无需点击切换，节点较多时横向滚动，支持从侧栏图标定位。
选择工单及办理后保留筛选和列表位置；工单移出当前范围后仍保留详情，校验失败保留填写的意见。
窄屏在列表和详情间切换，可返回列表；禁用 JavaScript 时仍可使用普通页面和 POST 表单。
列表最多显示 100 条，不进行自动轮询。统计包括待办、即将超时、已超时、进行中和本月完成；
本月完成按登记外部付款申请后的工单完成时间统计，不代表实际已付款或已收款。部署需执行全部数据库迁移、更新静态资源并重启 Web。
创建工单时同步生成《维护服务工单》电子表单，无需重复填写。
服务工单打印时，纸张左上方显示工单编号的 Code 128 条形码，甲方盖章栏右下方显示核验二维码。
扫码登录后可查看对应表单版本、工单基本信息、办理记录和付款申请提交时间，并进入合同付款信息。
核验页仍校验工单、材料及办理记录的查看权限；付款申请时间不代表实际付款时间。
部署此功能时需同步安装包依赖（新增 `python-barcode`）、收集静态文件并重启 Web。

工单业务日志接入 NetBox 原生“Core > 变更的对象”，仅保留七类：创建流程、批转流程、
打开流程（查阅流程）、保存表单、打印表单、上传材料、删除材料。提交、同意、退回、转办
和加签统一归为“批转流程”；上传覆盖归为“上传材料”。每个业务动作通过一条操作记录
关联所属工单，避免同时记录工单、任务、材料内部保存产生的重复条目。摘要仅显示操作类别，
详情保留必要的工单、节点、材料版本及目标人员信息；完整意见和审批证据仍保存在业务历史。
新建流程自动生成表单、保存表单自动生成版本均不重复记账；无改动保存仍记录为“保存表单”。
打开记录仅在明确进入工单详情时生成，列表查询、搜索、历史刷新和材料预览、下载不单独记录。

打印按钮及 HTML 表单的浏览器打印事件记录为“打印表单”（发起打印或另存为 PDF），
不代表打印完成，取消打印仍保留发起记录。浏览器原生 PDF 工具栏无法报告打印动作。
此功能无需新增数据库迁移，部署时更新插件、重新收集静态文件并重启 Web；已有日志不改写。
查看日志沿用 NetBox 原有权限，流程配置等其他对象的原生日志保持原有行为。

三个阶段依次为：工单下单、工单验收、付款申请。
插件菜单中的“维护流程定义”入口（`/plugins/oa/maintenance/definition/`）
展示当前代码定义的阶段、节点顺序、处理角色、材料要求、退回位置和付款状态变化。
等待时长、流程时限、预警时长及打印明细中的服务时长统一按天、小时、分钟展示；满一天显示为“6天14小时24分钟”等格式，不足一天省略天数，不足一小时仅显示分钟。
默认按阶段展示流程图：实线连接顺序节点，红色虚线连接实际支持的退回位置。
可缩放、隐藏退回路径，点击节点跳到详细规则；图形直接在页面绘制，无外部图形服务依赖。
选择有查看权限的流程配置，可查看四类角色的用户组映射、启用状态及节点时限。
此页面只读，需要维护工单或维护流程配置的查看权限；已启动工单继续使用启动时的流程快照。
当前流程包含 14 个顺序环节和 1 个仅退回时进入的工单修正环节，按阶段分别为 5、6、3 个顺序环节。
流程内置填报、审核、扫描材料上传、用印、生成付款和付款等节点，并提供审批签名、材料版本及权限规则说明。
最后的付款节点由线路主管登记外部付款申请单号和申请结果，系统不会代替外部审批或执行付款。
在“付款”环节登记外部申请单号后完成工单，状态为“付款申请已提交”。

首次使用：

1. 执行数据库迁移和 `collectstatic` 后，在插件菜单打开“维护流程配置”。
2. 配置复核人、部门负责人、上级负责人、印章管理人，共四种角色；配置节点时限和提前提醒时间，默认 24 小时、提前 4 小时。
   可勾选“设为默认流程配置”。默认配置必须启用，设置新默认会取消旧默认。
   发起页优先选中有查看权限的默认配置；只有一个可用配置时自动选中，多配置未设置默认时手动选择。
3. 为线路主管和角色组配置下表中的 NetBox 对象权限。
4. 线路主管本人发起维护工单，选择 netbox-contract 外购合同，填写服务项目及服务位置，保存草稿，申请人签名后直接提交工单复核。
   新增页打开时预留年月及随机尾码，选定合同时自动预览完整编号。编号格式为 `Y-GD两位年份两位月份合同类型码随机尾码`（如 `Y-GD2611K03B`）；草稿阶段切换合同会更新类型位，首次提交审批时锁定完整编号。服务端校验编号凭证，数据库唯一约束防止重复。
   维护工单在表单、列表、详情、打印及 API 中统一使用工单编号，不再包含工单名称。
   尾码按 `01–99` 在前、`A–E` 在后组成，从当月未使用的组合中安全随机选择，不递增。同月不重复，不同月份可复用尾码。打开新增页时预留编号，未保存的预留编号不回收；每月最多预留 495 个编号，用完后明确提示。
   编号规则更新需执行数据库迁移 `0025`，移除旧年度流水号表；不转换已有测试编号。
   合同类型码按类型 ID 固定映射：`1 外购资源 → W`、`2 代维-框架 → K`、`3 代维-日常 → D`。
   首次提交后即使退回补正并修改合同，编号及编号类型仍保持不变；当前合同类型单独展示，修改前后的合同及类型记录在操作日志中。
   合同类型未设置或未配置代码时可保存草稿，但不能提交；外部合同类型改变后，草稿须重新保存并签名。升级需执行迁移 `0026`，仅增加编号预留关联及类型快照，不转换研发测试数据。
   可通过插件配置 `contract_type_number_codes` 覆盖类型 ID 到一位大写字母／数字的映射，各代码须互不重复。
5. 下单审批后，印章管理人按已审批的系统工单办理用印，发起人通过材料上传弹窗上传对应版本的用印件。
   进入验收申请后填写工单验收单，并上传服务报告、服务结算单；经验收申请、复核及部门审核签名、公司审批、验收用印及用印件上传后办理付款申请。

工单下单阶段的正常审批顺序为：**工单复核 → 工单部门审核**。申请人在新增／编辑页面保存草稿、扫码签名后直接提交复核，不再进入“发起工单”节点。复核或部门审核退回时进入独立“工单修正”节点，修改表单并重新签名后再送复核；修正期间工单仍为进行中。
部门审核完成后依次办理：**工单公司审批 → 服务工单用印 → 上传用印后服务工单**。取消“服务工单”上传及“服务工单用印部门审核”节点，无需上传用印前扫描件。工单公司审批直接使用已签字审核的系统工单表单；印章管理人按该表单用印，发起人上传关联该表单版本的用印后扫描件后进入工单验收。公司审批退回时进入工单修正，修订表单并重新签名后依次经过复核、部门审核和工单公司审批。
工单验收阶段依次办理：**验收申请 → 验收复核 → 验收部门审核 → 验收公司审批 → 验收用印 → 上传用印后验收单**。
验收申请和用印后上传由发起人办理，复核使用复核人组，部门审核使用部门负责人组，公司审批使用上级负责人组，用印由印章管理人办理。
申请时填写工单验收单，基本信息从当前工单带入且只读；服务效果选项为“优、良、合格、不合格”，结算金额支持两位小数并按精确金额保存。
同时上传至少一份服务报告和一份服务结算单的 PDF、PNG 或 JPEG 扫描件，两类附件支持多份、覆盖和逻辑删除，每份最大 20 MB；均无需用印，也没有用印后上传环节。
验收申请、验收复核和验收部门审核必须完成本人手写签名，日期由系统记录，签名绑定具体验收单版本；验收公司审批无需签名。退回时进入验收申请，修订表单并更新两类附件后重新办理，旧签名不计入新版。
验收单仅一份，以版本保存修订；审批后办理用印，由发起人上传关联本次审批验收单的用印扫描件。打印与服务工单共用条形码和二维码，二维码核验需要登录和对应权限。
生成付款以用印后验收单和本次服务结算单为依据，付款审核仍由部门负责人办理。
新增验收材料及阶段选择需执行迁移 `0027`，不升级研发测试实例的流程快照；请新建测试工单验证。
生成付款和付款审核环节的专属操作均仅保留一个“付款信息”按钮，链接到对应外购合同详情页。
用户在合同详情页自行维护付款信息，并返回 OA 提交或审批；OA 不选择、引用或校验具体付款记录。
按钮需要对应外购合同的查看权限；付款的新增、修改及权限控制由 netbox-contract 原有页面负责。
付款申请阶段依次为“生成付款 → 付款部门审核 → 付款”。生成付款时上传付款通知书、电子发票，付款部门审核时查阅核对；最后由线路主管办理“付款”，登记外部申请单号后完成工单，付款状态为已申请。
两个审核节点分别使用“维护流程配置”中的“复核人”和“部门负责人”用户组，不固定指定姓名。
将审核人员加入对应用户组，并授予该工单的查看权限和任务办理权限；组内有权限的人员可直接办理。
用户组分配在工单启动时写入流程快照；配置调整用于之后启动的工单。管理员代办和显式转办保留办理记录。
发起人不能审批自己发起的工单，包括加签和管理员代办；即使属于审批组或为超级管理员，也须由其他有权限的审批人办理。审批转办、加签不能指定发起人。
申请人首次提交及两个审核节点记录实际签名人的姓名、账号与日期，打印版按对应材料版本显示签字，历史签字不随账号改名变化。

合同选择只读取有查看权限的 `netbox_contract.Contract`（外购合同），不读取收入合同。
选择后自动带入合同编号、外部签约方（服务单位），以及自定义字段 **`ProvincesOfResources`**
中多个 `dcim.Region` 对象的名称（服务省市）。自动带入地区名称需要对应地区的查看权限。
服务省市从 NetBox `dcim.Region` 地区模型中多选，合同自动带入后可重新选择。
框架合同未配置省市或无法自动带入时，直接选择有查看权限的地区；不接受自由文本或无权限、已删除的地区。
选择结果在工单编辑、表单修订和校验失败后重新显示时保留；API 使用 `service_region_ids` 地区 ID 列表。
工单同时保存地区 ID 和名称快照；历史文字能唯一匹配地区时会在编辑页选中，否则提示重新选择。
合同编号和服务单位由服务端重新读取，不能通过表单或 API 手工覆盖。
工单保存合同 ID 和文字快照；历史工单不自动匹配合同，修改时须重新选择。
API 创建工单须传 `contract_id`；未传 `service_region_ids` 时默认使用合同地区，框架合同须显式选择地区。
`contract_number`、`supplier`、`service_region` 为服务端生成的文字快照。
若自定义字段改名，可在 `PLUGINS_CONFIG["netbox_oa"]["contract_service_region_field"]` 配置新名称；
合同自定义字段应配置为“多个对象（multiobject）”，关联对象类型为“DCIM > 地区（dcim.region）”，
适用对象为外购合同；该字段由 NetBox 配置，合同插件源码没有固定定义其类型。
未安装合同插件、无合同查看权限或合同资料不完整时会提示错误；地区无法自动带入时可重新选择。
本次新增迁移为 `0012_maintenanceorder_service_region_ids`，部署需执行 `migrate` 和 `collectstatic`。

任务在事务内先锁工单再锁任务，数据库约束保证一个工单最多有一个待处理节点。
组任务在开始办理前对同组有权限的人员开放；首次成功保存表单、上传材料、审核或办理操作时自动确定办理人，其他组员不能继续办理；转办需目标人员具备处理权限，组任务的
转办目标必须属于原经办组。加签在当前审核节点之后插入一个指定人员的审核节点，
组审核节点的加签人员也必须属于原经办组；付款计划在全部加签完成后才标记已提交。
草稿可由申请人或线路主管撤销；进行中的终止仅允许超级管理员填写原因办理。

退回时必须说明原因，系统返回相关填报节点，并重新执行后续审核。涉及材料的补正必须
保存修订表单或上传新附件版本，不能直接重用原版本。已完成阶段的材料不能被覆盖，工单业务信息仅可在草稿或
工单修正节点修改。每次材料提交、转办、加签、退回和办理完成都保留操作历史。

六种材料按三类组织，公司表单与上传附件分开办理：

服务结算单卡片提供“计费明细”入口，一份工单只维护一份费用明细，其中的计费条目可增减，数据保存在 `billing_data` JSON 字段中。
验收单金额右侧的维护图标直接打开 NetBox 原生 Bootstrap 弹窗，保留底层遮罩，宽屏最大宽度为1320px；底部使用标准“取消”“保存”按钮。保存后关闭弹窗并回填金额，不刷新或清空验收单中未保存的其他字段。
计费项目来自工单所属外购合同的 `maintenance_pricing`：固定单价按数量计算，分档按规格值与已确认边界匹配，首班次及超时按起止时间和合同进位规则计算；减去各条扣费金额后逐条按分四舍五入，再汇总。
费用明细独立于扫描件，无需先上传服务结算单，也不要求关联扫描件或文件份号；可在验收申请环节直接维护费用明细。保存直接更新当前记录，不新增计费版本或展示计费历史；已生成验收单中的审批金额快照不受修改影响。提交后费用只读。扫描件仍按原材料流程维护，不参与费用条目的关联。
配置合同收费标准后，验收单金额由该工单费用明细中的计费条目自动汇总，不能手动改价；计费明细变更后，须重新保存验收单并签名。扫描件上传或替换不影响独立费用明细。没有配置收费标准的历史合同保留原手填金额方式。
升级需执行数据库迁移至 `0032` 并收集静态文件；已有多份费用明细自动合并计费条目与金额，原验收审批快照不变。不再提供整份费用的新增、删除入口。

- 维护服务工单：按样表填写甲方信息、服务项目及服务要求，保存后生成不可覆盖的表单版本。
- 资料库统一按“电子版”“用印后”“扫描件”三类展示：电子版包含需要填写的维护服务工单、工单验收单；用印后包含这两份表单打印、用印后上传的扫描文件；扫描件包含服务报告、服务结算单、付款通知书、发票。电子版与用印后分别展示各自的文件状态和版本。
- 服务报告：验收申请时上传扫描件，支持多份，无需用印。
- 服务结算单：验收申请时上传扫描件，支持多份，无需用印。
- 工单验收单：验收申请时填写，包含服务效果和结算金额；申请人、复核人和部门审核人三处签名及日期由对应节点生成，用印后上传关联本次审批表单的扫描件。
- 付款通知书、电子发票：无需填写，直接上传材料扫描件，无需用印审批；材料索引、预览及下载文件名统一标识为“扫描件”（含已有上传材料）。
- 两类付款扫描件在“生成付款”节点上传并校验必填，“付款部门审核”节点可查阅，最后的“付款”节点仅登记外部付款申请。升级执行数据库迁移 `0028`，移除未结束工单中合同复印件、发票验真结果的必填要求；已有文件保留查阅，不再提供上传入口。

打印页面提供“打印 / 另存为 PDF”，使用浏览器 A4 打印；签字盖章栏不自动代签。
表单保留生成时的数据，历史版本可再次查看打印。修改工单基本信息时，已有工单表单同步生成新版本。
签字盖章扫描件单独上传并关联当前原件版本，不能用旧版扫描件满足修订后的材料要求。
部署本次更新需执行数据库迁移（含 `0004_material_forms_and_scans`）及 `collectstatic`。

材料分别记录版本、经办人、材料形态及说明；节点完成时保存所依据的材料版本。
单文件最大 20 MB，附件支持 PDF、DOCX、XLSX、PNG、JPEG，扫描件支持 PDF、PNG、JPEG。
材料保存于受保护目录，下载同时校验材料和所属工单权限，不提供直接文件 URL。
可在插件配置中指定目录：

```python
PLUGINS_CONFIG = {
    "netbox_oa": {
        "maintenance_storage_root": "/opt/netbox/oa-private",

}
```

该目录必须由 NetBox 进程可写，并加入备份。默认位于 `MEDIA_ROOT` 的同级
`netbox_oa_private` 目录，不应通过 Web 服务器静态发布该目录。

合同编号和故障编号作为业务引用保存；关联对象功能可绑定具有 NetBox 对象权限的
合同、故障、站点或设备模型。插件不自动创建其他插件的合同或故障对象。

维护 API 位于 `/api/plugins/oa/maintenance/`：

| --- | --- |
| `policies/` | GET / POST |
| `policies/{id}/configure/` | POST |
| `orders/` | GET / POST |
| `orders/{id}/start/`、`withdraw/`、`terminate/` | POST |
| `tasks/`、`tasks/{id}/` | GET |
| `tasks/{id}/complete/`、`return/`、`claim/`、`transfer/`、`countersign/` | POST |
| `documents/` | GET / POST（文件上传使用 multipart） |

材料 API 返回 `kind`（form/attachment/scan）、`form_data` 和 `source_document`，
用印扫描件上传须提供当前原件的 `source_document_id`，维护服务工单电子版通过页面表单生成。
验收申请中的服务报告、服务结算单直接上传扫描件，`state=scan`，不提供 `source_document_id`。

材料状态统一为 `electronic`（电子版）、`scan`（扫描版）。用印后上传环节上传扫描件时，系统自动记录上传任务和用印标记，并逐份关联本次审批原件；客户端不能自行指定用印标记。表单、API 和服务层仅接受 electronic、scan 两种材料状态，旧状态值直接拒绝。

验收申请中的服务结算单只校验扫描件，`complete` 请求无需提供结算期；付款周期在 netbox-contract 原有新增付款页面填写。
生成付款和付款审核的 `complete` 请求无需提供付款 ID、日期或金额。付款信息由用户在外购合同详情页维护。
外部节点须包含 `external_reference`。转办和加签须包含 `user_id` 与 `comment`。
普通 API 不允许直接修改工单、任务状态或付款结果。

升级后执行 `manage.py migrate`、`manage.py collectstatic --no-input`，然后重启 Web 和 worker。

## 安装

使用 NetBox 的 Python 环境安装本项目，不要通过 PyPI 安装同名的 NetBox 包：

```bash
/opt/netbox/venv/bin/pip install /path/to/netbox-oa
```

在 NetBox `configuration.py` 中启用插件，保留原有插件：

```python
PLUGINS = ["netbox_oa"]
```

插件通过 `PluginConfig.django_apps` 自动注册 `django_fsm_log`，无需手工改写
NetBox 的 `INSTALLED_APPS`。在 `local_requirements.txt` 中加入本项目路径，
确保 NetBox 升级重建虚拟环境时仍会安装插件。

```bash
cd /opt/netbox/netbox
../venv/bin/python manage.py migrate
../venv/bin/python manage.py collectstatic --no-input
../venv/bin/python manage.py check
```

按部署方式重启 NetBox Web 进程与 worker。原生页面入口为 `/plugins/oa/` 下的
`definitions/`、`instances/`、`tasks/`，API 前缀为 `/api/plugins/oa/`。

## 最小使用流程

1. 在 NetBox 中创建审批用户组，将审批人加入对应组并授予对象权限。
2. 在 OA 工作流菜单中创建流程定义。`steps` 为按顺序执行的 JSON 数组：

   ```json
   [
     {"name": "部门审批", "group_id": 1},
     {"name": "运维审批", "group_id": 2}
   ]
   ```

3. 创建流程实例，填写标题、定义和业务 JSON 数据，保存后进入草稿详情。
4. 申请人提交草稿，系统仅生成当前节点的待办任务。
5. 审批组成员通过任务详情执行通过或拒绝；通过后生成下一节点的任务。
6. 最后一个节点通过后流程完成；申请人或超级管理员可撤销草稿和审批中流程。

## 权限与一致性

使用 NetBox 的对象权限，既校验模型权限，也通过 `restrict()` 校验对象约束。
建议申请人的实例 `view/change` 权限约束为 `{"requester_id": "$user"}`，
审批人的任务 `view/change` 权限约束为对应 `assigned_group_id`。

| 角色 | 对象类型与操作 |
| --- | --- |
| 流程管理员 | WorkflowDefinition 的 view/add/change/delete |
| 申请人 | WorkflowDefinition 的 view；WorkflowInstance 的 view/add/change |
| 审批人 | WorkflowTask 的 view/change；按需授予关联实例的 view |

审批人还必须属于当前任务的审批组；超级管理员可代审批。
流程实例不提供普通 API 编辑或删除，任务仅提供查询和审批动作。
状态、申请人、处理人、快照均由服务层维护，不接受客户端直接修改。
API 动作保留 NetBox 令牌的写权限限制，页面动作仅支持 POST 并使用 CSRF 保护。

提交时冻结节点快照，定义的后续修改不影响在途流程。事务内先锁实例、再锁任务；
重复或非法审批会回滚。数据库约束保证同一流程最多一个待审批任务、同一节点只能生成一次。
审批组通过保留表及 PROTECT 外键保护，尚未到达的节点也不会因组被删除而失效。
业务数据目前保存为 JSON，后续可在 `services.py` 扩展具体业务集成。

## 开发与验证

### 首页工单待办小组件

在 NetBox 首页编辑仪表盘，还可添加“工单 TODO”小组件（默认 4×4）。列表仅显示工单号和申请人，点击工单号进入详情，勾选复选框即可快速办理：审核／会签自动记录“同意”，用印自动记录“已用印”，成功后刷新待办。填写、上传、外部业务单号及签名节点（含工单复核、工单部门审核）的复选框禁用，须进入详情办理。快速办理仍校验当前任务、人员／组分配、对象权限和材料完整性，保留正常办理记录；原有数量小组件可继续使用。

小组件将“待办”和“可代办”并列展示，沿用工单列表状态的分配规则：分配给当前账号或所在组的“待你审批／待你处理”计入待办；有办理权限但分配给其他人员或组的计入可代办。两项分别按工单去重。“草稿”在下方单列，只统计当前账号作为申请人的草稿。

在 NetBox 首页编辑仪表盘，添加“工单待办”小组件（默认 2×2）。小组件按当前用户的任务办理权限、工单查看权限及人员/组分配，统计进行中且待处理的工单数量，同一工单只计一次，包含审批及其他办理节点，不计未提交草稿。管理员沿用工单待办页的权限规则。

有待办时显示橙色提示图标及数量，无待办时显示绿色完成图标和“暂无待办工单”；下方单独显示“草稿”数量，仅统计当前账号作为申请人且有查看权限的草稿工单，管理员也只统计个人草稿。点击待办进入工单 V2 的“待办工单”页，该页面也会展示用户可处理的草稿。更新插件并重启 NetBox 后可添加此组件，无需数据库迁移。

## 手机手写签名

工单复核、工单部门审核，以及验收申请、验收复核、验收部门审核的办理区域在无签名时显示“添加签名”，点击后弹出二维码。手机无需登录，书写并提交后弹窗自动关闭，电脑端显示签名和删除按钮 ×。点击 × 撤销本次签名并恢复“添加签名”。点击“同意”或提交本环节时确认使用当前签名，不再要求单独确认。二维码有效期为 15 分钟，生成二维码即由当前办理人开始办理。关闭未签字的弹窗会取消本次请求；重新生成、删除、转办或退回会使原链接失效。已上传的链接不能再次提交。

签名绑定审核人、节点和对应的维护服务工单或工单验收单表单版本，审核通过后随该版本打印。手机采集入口使用短时链接和独立签名提交凭证校验，不依赖扫码浏览器的 Cookie 或 Referer；电脑端操作仍使用登录和 CSRF 校验。图片保存在数据库中，通过权限检查后展示，删除操作撤销使用并保留审计记录。上述签名节点必须完成本人手写签名，填写文字意见不能替代；表单修订后旧签名不计入新版。

更新部署时安装项目依赖（新增 `qrcode[pil]`），执行 `manage.py migrate`、收集静态文件并重启服务。二维码采用当前访问地址生成，手机必须能访问该 NetBox 地址；反向代理应正确传递外部 HTTPS 主机名和协议。

当前流程：14 个顺序办理环节，另有仅在退回时进入的工单修正节点。草稿可不签名保存，继续显示在待办工单中；首次提交审批必须有绑定当前表单版本的申请人签名。签名按钮先保存草稿并在原页面展示二维码，上传签名后仍需点击提交审批。表单修改后必须重新签名，首次提交同时冻结流程快照并创建复核待办。修正后保留原审批历史并重新经过复核、部门审核和工单公司审批。

开发阶段只维护当前流程，不兼容旧节点、旧材料状态或旧付款字段。流程变更后使用新建测试实例，不自动升级进行中实例的流程快照。
迁移 `0020` 删除废弃付款字段和无效角色配置，保留四种审批及用印角色；历史迁移文件保留用于从空数据库安装。部署需 migrate、collectstatic 并重启 Web 和 worker。

材料上传统一使用 NetBox 标准尺寸的上传图标按钮，在当前窗口以带底层遮罩的弹窗打开独立上传表单。维护服务工单和工单验收单各一份，修订保留历史版本；服务报告、服务结算单支持多份，每份独立编号，上传时选择“新增材料”或“更新已有材料”，更新保留份号和历史版本。其他材料可批量上传，每份最大 20 MB。用印扫描件逐个关联本次审批的具体表单版本，预览中同时展示审批件和关联用印件。上传成功后关闭弹窗并刷新当前材料内容，取消时保留底层页面。上传入口及页面均按当前流程节点和用户权限控制。
新上传文件自动命名为“工单号_材料类型_份号_审批件或用印后_v版本.扩展名”，保留原始文件名供追溯；历史文件保持存储位置，显示和下载时使用统一命名。升级时需执行数据库迁移 `0022_material_item_revisions`，为已有材料补充份号及维护服务工单的更新关系。
当前材料卡片按本次办理节点显示上传状态、最近上传日期和版本；用印材料全部补齐后才标记完成，历史节点及退回前的上传不计为本阶段完成。

OA 操作结果、错误、校验和动态提醒统一使用 NetBox 原生右下角 Toast，异步办理与上传、审阅、签名弹窗共用同一提示入口。工单复核、工单部门审核、验收申请、验收复核、验收部门审核均须签名后批转；工单公司审批和验收公司审批无需签名。
